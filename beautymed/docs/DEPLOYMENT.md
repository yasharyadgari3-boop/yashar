# راهنمای راه‌اندازی BeautyMed روی هاست

> **هنوز هاست انتخاب نشده است.** این راهنما برای هر سروری نوشته شده که Node.js و PostgreSQL را اجرا کند (سرور مجازی، VPS ایرانی یا خارجی، یا سرویس ابری). وقتی هاست را انتخاب کردید، بخش «مخصوص هاست» را با هم کامل می‌کنیم. هیچ کد مخصوص یک هاست در برنامه نیست.
>
> **قبل از راه‌اندازی عمومی** باید این‌ها آماده باشد: درگاه پرداخت واقعی، سرویس پیامک واقعی، سرویس ترجمه، محتوای پزشکی بازبینی‌شده به‌جای متن نمونه، تأیید حقوقی قواعد (کد IRC، رضایت تصاویر، مجوز ترجمه‌ها) و نماد اعتماد الکترونیکی. تا این‌ها آماده نشده، سایت فقط برای آزمایش بالا می‌آید.

## ۱. آنچه هاست باید داشته باشد

| مورد | حداقل |
|---|---|
| Node.js | نسخه‌ی ۲۲ (LTS) |
| PostgreSQL | نسخه‌ی ۱۶ |
| حافظه | ۱ گیگابایت رم (۲ گیگابایت برای ساخت راحت‌تر) |
| دیسک ماندگار | برای پوشه‌ی فایل‌های خصوصی (مدارک نظام پزشکی و تصاویر محصول) |
| زمان‌بندی کار (cron یا مشابه) | برای دریافت مقاله‌ها و پاک‌سازی روزانه |
| گواهی HTTPS | برای beautymed.ir (بیشتر هاست‌ها رایگان می‌دهند) |

یک نکته‌ی مهم: فایل‌های خصوصی روی دیسک خود سرور ذخیره می‌شوند. هاست‌هایی که دیسکشان پس از هر استقرار پاک می‌شود (بعضی سرویس‌های «بدون سرور») مناسب نیستند، مگر اینکه بعداً ذخیره‌سازی را به یک فضای ابری خصوصی منتقل کنیم.

## ۲. تنظیمات (.env روی سرور)

همه‌ی متغیرها در `.env.example` با توضیح فارسی آمده‌اند. روی سرور واقعی:

- `DATABASE_URL`: از پنل هاست یا پایگاه داده‌ای که ساخته‌اید.
- `AUTH_SECRET`: یک مقدار تازه با `openssl rand -hex 32` (همان مقدار محلی را استفاده نکنید).
- `APP_URL="https://beautymed.ir"`
- `ADMIN_MOBILES`: شماره‌ی موبایل مدیر.
- `ALLOW_MOCKS_IN_PRODUCTION="false"`: سرویس‌های آزمایشی در نسخه‌ی نهایی کار نمی‌کنند؛ تا سرویس‌های واقعی وصل نشده، ورود با پیامک و پرداخت روی سایت واقعی کار نمی‌کند. این عمدی است.
- `PRIVATE_STORAGE_DIR`: یک مسیر روی دیسک ماندگار، **بیرون** از پوشه‌ی برنامه.
- `SITE_INDEXABLE="false"` تا روز راه‌اندازی (بخش ۶).

## ۳. نخستین استقرار

دستورها را یکی‌یکی در پوشه‌ی `beautymed` روی سرور اجرا کنید:

```bash
npm ci
```
نصب بسته‌ها. در پایان باید `added ... packages` ببینید و خطای قرمز نباشد.

```bash
npm run db:deploy
```
ساختن جدول‌های پایگاه داده. باید `All migrations have been successfully applied` ببینید.

```bash
npm run build
```
ساختن نسخه‌ی نهایی. در پایان فهرست صفحه‌ها می‌آید.

```bash
npm run start
```
اجرای سایت روی درگاه ۳۰۰۰. هاست باید درخواست‌های https://beautymed.ir را به این درگاه برساند (در پنل هاست یا با nginx؛ این بخش به هاست بستگی دارد).

`npm run db:seed` را روی سرور واقعی **اجرا نکنید**: کاربران و محصولات آزمایشی می‌سازد.

## ۴. بررسی سلامت

نشانی `https://beautymed.ir/api/health` باید `{"status":"ok"}` برگرداند. اگر پایگاه داده در دسترس نباشد، کد ۵۰۳ می‌دهد. این نشانی را در سرویس پایش (uptime) هاست یا یک سرویس رایگان پایش ثبت کنید.

## ۵. کارهای زمان‌بندی‌شده

| کار | دستور | پیشنهاد زمان |
|---|---|---|
| دریافت مقاله‌های تازه از PubMed | `npm run pubmed:fetch` | روزی یک بار، شب به وقت آمریکا (مثلاً ساعت ۱۰ صبح ایران) |
| پاک کردن نشست‌های منقضی و کدهای یک‌بارمصرف قدیمی | `npm run maintenance:cleanup` | روزی یک بار |
| پشتیبان‌گیری | `npm run backup` | روزی یک بار |

## ۶. روز راه‌اندازی: باز کردن سایت برای گوگل

تا وقتی `SITE_INDEXABLE` برابر `false` است، فایل `robots.txt` همه‌ی سایت را برای موتورهای جستجو می‌بندد و هر صفحه برچسب `noindex` دارد. پس از جایگزینی همه‌ی محتوای نمونه:

1. در `.env` مقدار `SITE_INDEXABLE="true"` بگذارید و برنامه را دوباره اجرا کنید (نیازی به ساخت دوباره نیست).
2. `https://beautymed.ir/robots.txt` را باز کنید؛ باید `Allow: /` و نشانی `sitemap.xml` را ببینید.
3. سایت را در Google Search Console ثبت و نشانی `https://beautymed.ir/sitemap.xml` را معرفی کنید.

صفحه‌های پنل، سبد خرید، پرداخت، ورود و جستجو همیشه از نتایج جستجو بیرون می‌مانند.

## ۷. پشتیبان‌گیری و بازگردانی

`npm run backup` دو فایل در پوشه‌ی `backups` می‌سازد: نسخه‌ی کامل پایگاه داده (`.dump`) و فایل‌های خصوصی (`.tar.gz`). این پوشه اطلاعات شخصی پزشکان دارد:
- فقط مدیر سرور به آن دسترسی داشته باشد (اسکریپت دسترسی را محدود می‌کند).
- یک نسخه را روزانه به جای دیگری (فضای ابری خصوصی یا سرور دوم) منتقل کنید؛ پشتیبانی که فقط روی همان سرور باشد، با خراب شدن سرور از بین می‌رود.
- پشتیبان‌های قدیمی‌تر از مدتی که وکیل تعیین می‌کند را پاک کنید.

**بازگردانی** کار برگشت‌ناپذیری است و داده‌های فعلی را جایگزین می‌کند. پیش از آن حتماً یک پشتیبان تازه بگیرید و اگر مطمئن نیستید، با من هماهنگ کنید:

```bash
pg_restore --clean --if-exists --no-owner --dbname="نشانی پایگاه داده" backups/beautymed-تاریخ.dump
```

```bash
tar -xzf backups/private-تاریخ.tar.gz -C "پوشه‌ی بالای PRIVATE_STORAGE_DIR"
```

بازگردانی را هر چند ماه یک بار روی یک پایگاه آزمایشی امتحان کنید؛ پشتیبانی که امتحان نشده، قابل اعتماد نیست.

## ۸. به‌روزرسانی و برگشت

برای نسخه‌ی تازه: پشتیبان بگیرید، کد تازه را بگیرید، بعد `npm ci`، `npm run db:deploy`، `npm run build` و اجرای دوباره.

اگر نسخه‌ی تازه مشکل داشت: کد نسخه‌ی قبلی را برگردانید و `npm ci && npm run build` و اجرای دوباره. تغییرهای پایگاه داده‌ی این پروژه فقط «افزودنی» نوشته شده‌اند، پس نسخه‌ی قبلی با پایگاه تازه کار می‌کند. اگر روزی تغییری حذف‌کننده لازم شد، پیش از استقرار جداگانه هماهنگ می‌کنیم.

## ۹. امنیت روی سرور

- سربرگ‌های امنیتی (CSP، HSTS، جلوگیری از قاب‌گذاری) را خود برنامه می‌فرستد. HSTS فقط روی HTTPS اثر دارد؛ پیش از فعال شدن HTTPS سایت را عمومی نکنید.
- وقتی درگاه پرداخت واقعی انتخاب شد، نشانی آن باید در `form-action` سیاست CSP (فایل `next.config.ts`) اضافه شود.
- محدودیت تعداد درخواست ورود در پایگاه داده شمرده می‌شود و با چند نسخه‌ی هم‌زمان برنامه هم درست کار می‌کند. محدودیت‌های دیگر (خبرنامه و درخواست ترجمه‌ی متن کامل) در حافظه‌ی هر نسخه است؛ اگر هاست چند نسخه اجرا کند، باید یک انبار مشترک اضافه کنیم.
- پیش از هر استقرار `npm audit --omit=dev` را اجرا کنید؛ باید `found 0 vulnerabilities` ببینید.
